TWO CORRECTED EDGE CASES

1. Numeric input boundaries. Oversized browse category/page values previously caused SQLite integer-conversion errors; oversized notice IDs could fail similarly. Browse now rejects unsafe numbers with HTTP 400, and notice handlers reject out-of-range IDs with HTTP 404 before querying SQLite. Tests also check valid filtered pagination, existing safe fallbacks, and rejection of invalid category forms without changing notices.

2. Full-backup manifest boundaries. The backup writer and restore reader now share a 1 MiB UTF-8 manifest limit. An oversized manifest is rejected before a ZIP is published; restore rejects it before creating its destination. A manifest exactly at the limit is accepted. Regression checks cover rejection, cleanup, unchanged source data and the exact boundary. Archive format and public commands remain unchanged.

METHOD AND LIMITS

The checks use the bundled Windows Python, Flask test clients and real temporary SQLite databases. They cover authentication, permissions, CSRF, notice persistence, media delivery, photo validation, analytics, recorder logic, simulated locker state, backup and scratch restoration. Passing tests establish the checked behaviors, not exhaustive correctness or production security.

Media checks verify static responses and alt-attribute presence; they do not establish visual quality or screen-reader usability. Recorder timing uses a controlled clock in tests; no measured human attempt is represented. Locker events are software simulation, with no physical sensor or door verification. Backup boundaries use small fixtures and patched limits; no 9,999-file or 512 MiB stress archive was created.
